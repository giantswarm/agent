## [Unreleased]

### Changed

- The ATS smoke (`execute-chart-tests`) runs on the platform's real runtime instead of asserting acceptance by the CRDs alone: on the kind cluster the CI job creates from `.ats/kind-config.yaml` (Kubernetes 1.35+, the `ClusterTrustBundle`, `ClusterTrustBundleProjection` and `PodCertificateRequest` gates, the `certificates.k8s.io/v1beta1` API) the tests bring up Agent Substrate (the Giant Swarm line `giantswarm/substrate` at `v0.0.27-gs.2`: the CA/JWT-pool bootstrap as a Job, the chart with its bundled database and snapshot store) and the kagent line (`giantswarm/kagent-upstream` at `v0.11.0-gs.3`: the controller wired to Substrate, a WorkerPool of gVisor workers, the bundled database, a placeholder ModelConfig) and the platform Harness (the Go ADK image by digest, admission by the label `agent-platform.giantswarm.io/harness`), then install releases of the chart and assert `status.harnesses[]` for the Harness: a release with `tests/ats/values-smoke.yaml` (every mapped field, a public git skill pinned to a commit) and a release with the default values reach `Ready` for their generation with their `RemoteMCPServer` accepted; `toolset: ["preset:none"]` reaches `Ready` with no `RemoteMCPServer`. The wait fails fast, with the reason, when no Harness admits the template, when the Harness's WorkerPool has no ready worker, and when the Harness image cannot be pulled (three functional cases). Every pin is named in `.ats/main.yaml` with the bump procedure; the eight CRDs of both lines come from the same tags via `cluster-crds`, and a half-done bump is refused before anything is installed.

### Fixed

- The `helm.sh/chart` and `app.kubernetes.io/version` labels stay valid at any chart version: helm-controller installs every OCI chart as `<version>+<digest>` and the `+` becomes `_`; a long branch-build version (`0.6.2-dev.<branch>.<date>.<time>.h<sha>+<digest>`) was cut at 63 characters right on that `_`, and the apiserver rejected every object of the release (`UpgradeFailed`, server-side apply). After the cut every trailing `-`, `.` and `_` is stripped now; unit tests render both objects at such a version. Release versions (`1.0.0+<digest>`) were never affected.

- **BREAKING** changed: chart 1.0 renders the kagent API v2 shape (`kagent.dev/v1alpha3`): an `AgentTemplate` named after the agent plus, unless the agent is chat-only (`toolset: ["preset:none"]`) or `muster.enabled` is false, the agent's own muster `RemoteMCPServer` — muster's URL, `STREAMABLE_HTTP`, the toolset as the static `X-Muster-Toolset` header in `spec.headersFrom`, the discovery opt-out label `kagent.dev/discovery: disabled`, never an `Authorization` header — which the template binds (`tools[].mcp.server`). No `kagent.dev/v1alpha2 Agent` is rendered; the chart installs only on a platform that serves API v2. The template carries the Harness admission label `agent-platform.giantswarm.io/harness` (new value `agent.harness`, default `kagent`) and the annotations `ui.giantswarm.io/display-name` and `ui.giantswarm.io/icon-url`. The value-by-value migration is the "Migrating from 0.x" table in README.md.
- **BREAKING** removed: `agent.runtime`, `replicas`, `resources`, `nodeSelector`, `tolerations` (the Harness and its worker pool own runtime, capacity and placement), `muster.serverRef`, `muster.allowedHeaders`, `muster.stsWellKnownUri` (the per-agent server replaces the shared cross-namespace one; the Harness propagates the caller's token) and `skills.gitAuthSecretRef` (no per-source credential in 1.x). The values schema refuses every removed key (`additionalProperties: false`).
- **BREAKING** changed: `skills` is a list of `{name, git: {url, commit}, path}` or `{name, oci: <ref@sha256:...>}` entries rendered into `spec.skills[].{name, source}`; the schema enforces the CRD's immutability rules (unique names, exactly one of git/oci, http(s) URL, 40- or 64-hex commit, digest-pinned image, relative path without `..`), so a branch, a tag, a short SHA or an image tag fails `helm template` with a message naming the field. `muster.toolNames` is renamed to `muster.tools` (the binding's `tools`). `extraTools` entries are v1alpha3 tool bindings. `extraAgentSpec` merges into the `AgentTemplate` spec only.
- added: `muster.url` (muster's MCP endpoint, default `http://muster.agent-platform.svc.cluster.local:8090/mcp`) and `muster.discovery.enabled` (default `false`: the discovery opt-out label is set).
- changed: helm-unittest suites and golden snapshots for both objects (`chart-test`); the ATS smoke pins the two v1alpha3 CRDs of the kagent line (`giantswarm/kagent-upstream`, `helm/kagent-crds/templates/` at the line's release tag `v0.11.0-gs.1`) via `cluster-crds`, installs the chart with `tests/ats/values-smoke.yaml` and asserts both objects were accepted with the contract, plus a functional `preset:none` scenario asserting no `RemoteMCPServer`.
- changed: the chart is published on branch builds (`push-chart`, the generated `.circleci/workflows.yml` with `gen.ci.branchPublish`), so a pull request's build can be consumed before it is released.

- added: top-level `toolset` value (list of `preset:`/`server:`/`workflow:`/`tool:` selectors) rendered as the static `X-Muster-Toolset` header on the muster tool entry (`spec.declarative.tools[].headersFrom`), so muster resolves the agent's tool surface per request. Exactly `["preset:none"]` renders no muster tool entry (chat-only agent); an empty list, more than 32 selectors, `toolset:<name>` (reserved) and malformed selectors fail the render with a pointer message. Unset renders exactly what the previous release renders. `muster.toolNames` is untouched. Render tests (helm-unittest, golden default) run in the new `chart-test` CircleCI job (`make helm-test`). Rollout step 3 of the Agent Tool Access plan (giantswarm/giantswarm#37435).
- changed: `muster.serverRef.namespace` defaults to `agent-platform` instead of `agentic-platform`, and the in-cluster muster discovery URL named in the `muster.stsWellKnownUri` documentation follows. Every management cluster now runs the platform in `agent-platform` (giantswarm#36869). Deployments that set the namespace explicitly are unaffected.
- changed: chart description now names the product "Giant Swarm Agent Platform" (renamed from "agentic platform").
- added: `skills.gitAuthSecretRef.name` value, rendered into the Agent's `spec.skills.gitAuthSecretRef` so `skills.gitRefs` can point at private git repositories. The chart never creates the referenced Secret — supply key `token` for HTTPS PAT/deploy-token auth, or a `kubernetes.io/ssh-auth` secret (key `ssh-privatekey`) for SSH deploy-key auth. Applies to all `gitRefs` entries.
- added: `agent.iconUrl` value, rendered into the Agent's `spec.iconUrl` (surfaced on the A2A AgentCard) so the agent's avatar can be set at creation time.
- changed: `muster.stsWellKnownUri` defaults to `""` (propagate-only) again, reverting the in-cluster discovery URL default released in v0.2.0. The platform switched to the dex-only trust model (muster must not sign tokens, muster#947): muster refuses every RFC 8693 exchange (`token_exchange_jwt_mode_required`), so a configured URI only produces a failed exchange per agent session before the runtime falls back to propagating the caller token — which is now the supported path, validated end-to-end on gazelle (the propagated Dex id_token is validated by muster's trustedIssuers). The value stays available for muster deployments that run in JWT mode.
- changed: `muster.stsWellKnownUri` now defaults to muster's in-cluster discovery URL (`http://muster.agentic-platform.svc.cluster.local:8090/.well-known/oauth-authorization-server`) instead of `""`, so tenants no longer set a per-installation value: the discovery document is served unauthenticated on the same Service the gateway URL uses and carries absolute (public) endpoint URLs, so the default is identical on every installation. Previously an unset value silently disabled the STS exchange — the agent forwarded the raw caller token (e.g. the kagent UI's Dex id_token), muster rejected it, and every tool call failed with `Unauthorized`. Validated end-to-end on gazelle (exchange succeeds through the in-cluster URL; kagent's discovery client imposes no RFC 8414 issuer/URL match). Set to `""` to restore propagate-only behavior.
- added: Initial version of the generic `agent` chart: renders a single kagent `Agent` (kagent.dev/v1alpha2) from a curated values surface — display-name annotation, description, system prompt, skills (OCI/git refs), admin-provisioned `ModelConfig` by name, shared muster gateway wiring with token-propagation env, resources/replicas/placement, and an `extraAgentSpec` deep-merge escape hatch. Ships `values.schema.json` encoding the curated contract.
- changed: Regenerated `.circleci` config with `devctl gen circleci` — adopt the dynamic-config setup workflow (`config.yml` + `workflows.yml`) and bump the architect orb to v9.5.2.
- changed: `app.giantswarm.io` label group was changed to `application.giantswarm.io`
- Fix template: avoid plus sign in label

# agent

Create a kagent agent on the Giant Swarm Agent Platform from a small, curated values surface. One chart release renders one AgentTemplate (kagent.dev/v1alpha3) and the agent's muster RemoteMCPServer, which carries its toolset; the Harness that runs the agent, the model configuration and the credentials are platform-owned and only referenced by name or label.

**Homepage:** <https://github.com/giantswarm/agent>

| agent.displayName | string | `""` | Human-friendly name, Unicode allowed. Rendered as the ui.giantswarm.io/display-name annotation on the AgentTemplate. Size-limited so it cannot become a description. |
| agent.description | string | `""` | Rendered into the AgentTemplate's spec.description. |
| agent.iconUrl | string | `""` | Fully qualified URL of the agent's avatar icon. Rendered as the ui.giantswarm.io/icon-url annotation on the AgentTemplate (the template has no icon field); the Dev Portal reads it. Populated by the agent-creation flows with the canonical avatar URL. |
| agent.systemMessage | string | `"You are a helpful agent.\n"` | The agent's system prompt. Rendered into the AgentTemplate's spec.systemPrompt. |
| agent.harness | string | `"kagent"` | Name of the platform Harness that runs the agent. Rendered as the label `agent-platform.giantswarm.io/harness` on the AgentTemplate — the label the Harness's allowedAgentTemplates selector matches. The platform ships the `kagent` Harness (the Go ADK runtime); a template no Harness admits is created and never becomes Ready. |
| modelConfig | object | `{"name":"default-model-config"}` | Which platform-provisioned ModelConfig the agent uses, referenced by name. kagent resolves it in the agent's own namespace. The chart never creates or mutates a ModelConfig, and tenants never handle LLM credentials. |
| modelConfig.name | string | `"default-model-config"` | Name of the platform-provisioned ModelConfig in the agent's namespace. Rendered into the AgentTemplate's spec.modelConfig.name. |
| context | object | `{"compaction":{"compactionInterval":null,"enabled":true,"eventRetentionSize":4,"overlapSize":null,"summarizer":{"modelConfig":"","promptTemplate":""},"tokenThreshold":24000}}` | How the runtime manages the conversation context while a turn runs. Rendered into the AgentTemplate's spec.context (kagent API v2). The kagent Harness (the Go ADK runtime) applies it to the agent; the Claude and Codex harnesses report it as ignored in the template's status warnings. Served by a kagent line that carries the field (giantswarm/kagent-upstream `0.11.0-gs.16` and later); an older kagent prunes it at admission and the history stays uncompacted, in silence. |
| context.compaction | object | `{"compactionInterval":null,"enabled":true,"eventRetentionSize":4,"overlapSize":null,"summarizer":{"modelConfig":"","promptTemplate":""},"tokenThreshold":24000}` | Compaction keeps the prompt bounded as a turn grows. Without it every tool result stays in the history verbatim and every later model call of the turn re-reads all of it: a status question that lists pods and events grows from 6 k to 60 k input tokens in ten calls, waits 9-19 s for the first token of every call after a large listing, and pays for the whole history on every call. The default is tail retention, the strategy that bounds a long tool loop: before a model call whose prompt has passed `tokenThreshold`, the runtime replaces everything but the last `eventRetentionSize` events and the turn's own question with one rolling summary (the previous summary is folded into the next, so the history is one summary plus a raw tail). A summary is a model call too — on the agent's own model unless `summarizer` names another — and it reads the events it replaces once, so a turn under the threshold pays nothing and a turn over it pays one summary per crossing instead of re-reading the whole history on every call; what leaves the raw tail survives only as the summary describes it (values and the registered tool names verbatim, per the runtime's default prompt). |
| context.compaction.enabled | bool | `true` | Render spec.context.compaction. `false` renders no spec.context at all: the agent keeps every word of a long turn verbatim and pays for re-reading it. |
| context.compaction.tokenThreshold | int | `24000` | Prompt token count at which tail-retention compaction summarises the history before the next model call — the last model response's prompt tokens plus an estimate of what the turn appended since. 24 000 leaves room for a system prompt with skills and the muster meta-tools (~6 k) plus a few tool results, and sits under where the first-token wait of an uncached pass starts to cost seconds on the platform's models. Needs `eventRetentionSize`; unset with `compactionInterval` set leaves tail retention off. |
| context.compaction.eventRetentionSize | int | `4` | Most recent events kept verbatim when compaction fires; everything older is summarised. A tool exchange is two events (the model's call, the tool's result), so 4 keeps the last two exchanges raw — the results the agent is still working with; the turn's own question is always kept. Needs `tokenThreshold`. |
| context.compaction.compactionInterval | string | unset: no sliding window | Sliding window: after every N completed turns of a conversation, summarise those turns as a whole (a second strategy, for long conversations of short turns; it never re-summarises, so it reduces growth without bounding it). Unset (the default) leaves it off. At least one of `tokenThreshold` and `compactionInterval` must be set. |
| context.compaction.overlapSize | string | unset | Already-compacted turns pulled back into the next window so consecutive summaries overlap; only with `compactionInterval`, and repeated text in the prompt is its price. |
| context.compaction.summarizer | object | `{"modelConfig":"","promptTemplate":""}` | Who writes the summaries. Both empty (the default): the agent's own model with the runtime's default prompt. |
| context.compaction.summarizer.modelConfig | string | `""` | Name of a ModelConfig in the agent's namespace to summarise with — a cheaper or faster model than the agent's. Its credentials and egress join the agent's revision; a change to it recompiles the agent. |
| context.compaction.summarizer.promptTemplate | string | `""` | Replaces the runtime's default summarisation prompt; must contain `{conversation_history}`, which the runtime fills with the rendered events. The runtime appends its tool-name instruction, so summaries keep the namespaced tool names the agent calls by. A prompt that asks only for brevity loses the concrete values the default carries forward; keep that instruction. |
| skills | list | `[]` | Agent skills, each pinned to an immutable source the Harness materialises for the agent. An entry is `{name, git: {url, commit}, path}` — a public http(s) git repository at a full 40- or 64-hex commit id, `path` the skill's directory within the checkout — or `{name, oci: <ref@sha256:...>}`, a digest-pinned image (`path` selects a directory within it). Rendered into the AgentTemplate's spec.skills[] as `{name, source: {git | oci, path}}`. Names are unique; exactly one of git and oci is set. A branch, a tag, a short SHA or an OCI tag fails the render with a message naming the field (the CRD refuses them at admission); the composers pin skills to a commit and re-pin them on demand. A private repository needs `skillsGitAuthSecretRef` below. |
| skillsGitAuthSecretRef | object | `{"name":""}` | One read credential for every private git skill. The chart never creates the Secret; the tenant provisions it in the agent's namespace (on the platform: the namespace the templates are compiled in). |
| skillsGitAuthSecretRef.name | string | `""` | Name of a Secret in the agent's namespace whose key `token` holds a read token for the https hosts of the agent's private git skills — a GitHub fine-grained PAT or App installation token, a GitLab PAT (the runtime presents `x-access-token` as the username). When set, every `skills[]` entry with `git` renders `source.git.credentialRef: {name, key: token}`; OCI sources are unchanged. The runtime offers the token to that source's https host only, on challenge only — a public repository with a credential still fetches. Empty (the default) renders anonymous fetches. Requires an `https://` URL on every git skill: the CRD refuses a credential on a plain http source, and the chart fails the render first, naming the skill. Secret missing: the template's Harness condition reads `ResolvedRefs=False` (`secret "…" not found`), no actor boots, and it recovers when the Secret appears. Wrong token: `Ready=False ActorTemplatePending` with git's authentication error in the actor's log. Rotate the Secret's contents, never its name — a renamed Secret means editing every referencing agent, a rotated token re-boots only the referencing agents. Served by a kagent line that carries the field (giantswarm/kagent-upstream, `0.11.0-gs.x`); a kagent without it prunes the field and fetches anonymously. |
| muster | object | `{"discovery":{"enabled":false},"enabled":true,"requireApproval":false,"timeout":"180s","tools":[],"url":"http://muster.agent-platform.svc.cluster.local:8090/mcp"}` | The platform's muster MCP gateway. Unless the agent is chat-only (toolset exactly `["preset:none"]`) or `enabled` is false, the chart renders a RemoteMCPServer named after the agent that points at muster and carries the toolset header, and binds it into the AgentTemplate's tools. |
| muster.enabled | bool | `true` | Wire muster into the agent's tools: render the agent's RemoteMCPServer and bind it in the AgentTemplate. |
| muster.url | string | `"http://muster.agent-platform.svc.cluster.local:8090/mcp"` | URL of muster's MCP endpoint, rendered into the RemoteMCPServer's spec.url. The default is the platform's in-cluster URL; set it for an installation whose muster is elsewhere. |
| muster.timeout | string | `"180s"` | How long one tool call through muster may run before the agent's runtime cancels it, rendered as given into the RemoteMCPServer's spec.timeout (a duration with a unit: `180s`, `5m`). Without the field kagent applies its own 30 s, which cuts a backend tool that legitimately runs longer — a write that creates a repository and opens a pull request in one call, a watch that blocks for minutes — although muster's own per-server budget for that backend allows more. The default matches the longest budget a muster backend declares in its spec.timeout, so a call is bounded by its backend, not by the caller. |
| muster.tools | list | `[]` | Set to narrow the binding to a subset of muster's meta-tools (`list_tools`, `call_tool`, ...); leave empty to bind every tool. Rendered into the binding's `tools`. A toolset is the way to narrow the tools behind the gateway. A Harness enforces a partial selection only when it can discover the server's tools; with discovery off (the default) it may expose the whole server and report a warning in the template's status.harnesses[].warnings. |
| muster.requireApproval | bool | `false` | Pause the agent before every tool call through muster until a person approves it. Rendered as `requireApproval: true` on the binding (kagent's human-in-the-loop): the Harness stops the task at `input-required` for each call and continues with the person's decision. It applies to the tools the binding exposes — `tools` when set, otherwise every muster tool. A client that negotiates kagent's HITL A2A extension (`https://kagent.dev/extensions/hitl/v1`) receives the structured `tool_approval_request` and answers it; one that does not sees a plain notice that human input is required. Off by default: the agent calls tools without asking. |
| muster.discovery | object | `{"enabled":false}` | Tool discovery by the kagent controller against muster. |
| muster.discovery.enabled | bool | `false` | Let the kagent controller list muster's tools when it reconciles the RemoteMCPServer. Off by default: muster is an OAuth resource server and the controller holds no user token, so the chart labels the server `kagent.dev/discovery: disabled` and the agent resolves its tools at run time as the signed-in person. Turn on only for a muster without OAuth. |
| toolset | list | unset: implicit full access, renders no header | The tools the agent is composed with: a list of selectors that muster resolves per request. Selectors are `preset:<name>`, `server:<name>`, `workflow:<name>` or `tool:<name>` with exact, case-sensitive names (regex `^(preset|server|workflow|tool):[^\s,]+$`); at most 32 inline, define a preset for more. `toolset:<name>` is reserved and refused; patterns, excludes, the read-only predicate and `label:` exist only inside presets. Rendered as the static `X-Muster-Toolset` header on the agent's RemoteMCPServer (`spec.headersFrom`, the selectors joined by `,`). Exactly `["preset:none"]` renders NO RemoteMCPServer and no muster binding at all, so a chat-only agent pays no context for meta-tools; an empty list fails the render (say `preset:none` instead). Unset (the default) renders no header and the agent keeps implicit full access to everything the gateway exposes to the invoking human. Built-in presets: `read-only`, `none`, `full`; the platform charts ship `infrastructure` and `agent-platform`. Composition, not authorization: the human's identity and the backends' own authorization stay the boundary. |

Servers and templates are referenced in the agent's own namespace. |
